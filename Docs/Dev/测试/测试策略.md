# 测试策略

- 目的：决定本项目测什么、不测什么，以及门禁顺序。
- 读者：实现者、评审、出包前检查。
- 关系：环境门禁命令见 [开发环境](../调研/开发环境.md)；用例见 [验收清单](验收清单.md)。
- 版本：v1.1
- 日期：2026-09-15

## 1. 结论

**要测。** 本项目线性 ADV，但存档、解锁、三类选项都容易被默认引擎行为带偏。Auto 已改为引擎默认，只确认没有被自管逻辑改掉。

测试以**手工验收清单**为主，以 **`renpy lint`** 为本地语法门禁。

不引入 UI 自动化。不引入本阶段 GitHub CI。不默认引入 pytest。

## 2. 层次

| 层 | 工具 | 本阶段 |
|---|---|---|
| 脚本静态 | `renpy lint`（引擎自带） | **要**。打开工程能跑后，每次出包前必跑；失败阻断出包 |
| 编辑器诊断 | Ren'Py 官方扩展 | 辅助，不作为门禁 |
| 纯逻辑单测 | pytest / unittest | **默认不要** |
| 手工功能 | 验收清单 | **主门禁** |
| UI 自动化 | Airtest 等 | **不要**（Ren'Py 成本高，线性阅读收益低） |
| CI | GitHub Actions | **不要** |

Ruff/Pylint/Flake8 不跑 `.rpy`。见开发环境。

## 3. 为何不默认 pytest

存档与解锁若用 Ren'Py `persistent` / slot，离开引擎跑 pytest 需要大量替身，假阳性高。

仅当出现**可在 CPython 直接 import、且 `import renpy` 为零**的纯数据模块（例如纯函数拼 `line_id`、纯字典校验）时，才允许给该模块写断言。放置位置届时再开 `game/system/pure/` 并更新本文。本版本不预建。

## 4. 手工测试规格

- 平台：Windows 必测；Android 在第一次出 APK 时测清单中标了「双端」的项。
- 构建物：必须脱离 Ren'Py 编辑器运行至少一次（清单 TC01）。
- 存档：含杀进程再开，不只点 Return。
- Auto：确认可自动前进，且点击后行为与引擎默认一致（通常退出 Auto）。禁止再测「点击不关闭」。
- 回放：鉴赏进节点后 Return，标题「继续游戏」仍是进鉴赏前的槽。

详细步骤与期望见验收清单。每条用例标注对应设计章节。

## 5. 何时跑

| 时机 | lint | 相关手工项 | 全量清单 |
|---|---|---|---|
| 实现某一 system 后 | 是 | 该子系统相关 TC | 否 |
| 合并到可玩主干前 | 是 | 存档 + Auto + 选项 | 否 |
| 出 Win 包 | 是 | 全量（Win） | 是 |
| 出 Android 包 | 是 | 双端项 + 返回键 | 是 |

失败处理：缺陷对应设计条款，修代码，不改验收期望来「过测试」。除非设计评审先改文档。

## 6. 不测范围

- 网页、iOS
- 真实美术/音频（本版本静音白图）
- 性能压测、内存曲线
- 无障碍读屏
- 多语言
