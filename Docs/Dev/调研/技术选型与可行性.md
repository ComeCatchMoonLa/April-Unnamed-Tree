# 技术选型与可行性

- 目的：论证引擎与关键技术能否支撑需求，并指出必须自研的点。
- 读者：设计、实现、评审。
- 关系：上游 [需求分析](需求分析.md)；开发机配置见 [开发环境](开发环境.md)；架构落点见 [架构设计](../设计/架构设计.md)。
- 版本：v1.4
- 日期：2026-09-20

## 1. 结论

本版本使用 **Ren'Py 8**（Python 3）。不引入第二引擎。产品范围内可行。

必须自研、不能当默认功能用的点：

1. 单槽 + 全局解锁（鉴赏解锁不进存档槽）
2. 自定义标题 / HUD / 设置，并关闭回滚、Skip、Hide、退出确认、默认存档柜

Auto **用引擎默认 auto-forward**（`preferences.afm_enable`）。不自管 pending/active，不改点击是否退出 Auto 的引擎语义。

开发环境（Cursor Profile「Py Dev」、插件、lint）见 [开发环境](开发环境.md)。摘要：工作区覆盖隔离 Ruff/Pyright，不卸载用户级 Python 工具；本地门禁用 `renpy lint`。

## 2. 引擎对比

| 方案 | 本地 Win+Android | ADV 对话框/Log/菜单 | 工期 | 结论 |
|---|---|---|---|---|
| Ren'Py 8 | 官方支持 | 现成，可关可换 | 最短 | **采用** |
| Unity | 可以 | 需自造 ADV 框架 | 过长 | 否决 |
| Godot | 可以 | 需自造 | 过长 | 否决 |
| Web VN（Tyrano 等） | 偏网页 | 与「不做网页」冲突 | — | 否决 |

采用理由：本地双端打包、对话框 / Log / Auto / 菜单现成，存档与鉴赏可用数据层扩展。允许使用引擎默认 UI 框架，但必须按设计替换菜单与存档，并关闭第 4 节清单中的默认功能。

## 3. 需求对照：默认能力 vs 自研

| 需求 | 默认能力 | 本项目做法 |
|---|---|---|
| 打字机 | `cps` | 可用。`preferences.text_cps` 随速度三档 |
| 点击先出完当前句 | 默认常见行为 | 保持 |
| Auto | 默认 auto-forward | **直接用**。HUD / `A` 只切换 `preferences.afm_enable`；点击是否退出跟引擎默认 |
| Log | History | 可用只读列表；禁止点击跳转 |
| 回滚 / Skip / Hide | 默认开 | **必须关** |
| 退出确认 | 默认常有 | **必须关** |
| 多槽存档柜 | 默认 save screen | **隐藏**。只暴露逻辑槽 `"0"`，经 `SaveStore` 读写 |
| persistent | 有 | 解锁放 `persistent`，不放槽 |
| 全屏/窗口 | 有 | 仅 Windows 暴露（设置项 + 引擎 `F`）；Android 恒定全屏 |
| 字体 | 可打包 | 必须打进包，不读系统字体 |
| 里线变暗 | Transform / overlay | 可行，固定 60% 黑，无渐变 |
| 表里底色 | screen 样式 | 可行 |
| Android 返回键 | 可绑 | 必须等于 Return，并遵守游玩/回放存档规则 |
| 音频 | 有 | 本版本不调用播放 |

## 4. 必须关闭的引擎默认项

实现时在配置层关闭，禁止 UI 再打开：

- `rollback`（滚轮、右键上一句、历史跳转回放）
- Skip / 快进
- Hide
- 退出确认框
- 默认存档柜界面

详见 [架构设计](../设计/架构设计.md)。

## 5. 可行性与风险

| ID | 项 | 可行性 | 风险 | 缓解 |
|---|---|---|---|---|
| R1 | 杀进程后从句首续玩 | 可行 | 若存打字进度或存错 `line_id` 会错位 | 只存 `line_id`，读档永远从该句开头 |
| R2 | 鉴赏不脏槽 | 可行 | **当前最高**。HUD 的 Return/节点自动存档误写入 | `play_mode = replay` 时所有写槽入口直接返回 |
| R3 | 有槽后无法从标题重开正篇 | 可行 | 玩家误以为丢档或卡死 | 有槽显示「继续游戏」，解锁 after 后同一键变为「后日谈」；正篇再玩走鉴赏回放；无清档 UI |
| R4 | Android 返回键 | 可行 | 被当成系统退出或弹出确认 | 绑定 Return；关确认；回放不写槽 |
| R5 | 字体双端 | 可行 | 未打包导致缺字或读到系统字体 | 只引用 `game/fonts/` |
| R6 | 里线变暗后可读 | 可行 | 深灰底 + 60% 暗可能过暗 | 默认色值见存档与播放文；验收时看安卓 |
| R7 | 句 ID 稳定 | 可行 | 重排序号导致旧档错位 | 只追加新号，不重排 |

结论：无一项会迫使换引擎。Auto 走引擎默认，不再单列实现风险。当前最高实现风险是鉴赏不脏槽。

## 6. 存档技术选型

采用：

- 用 Ren'Py 存档槽持久化 `SaveRecord` 字段
- 用 `persistent` 持久化 `PersistentUnlocks`
- 所有读写经 `SaveStore` / `UnlockStore`；UI 只传 `slot_id`

不采用：

- UI 直接 `renpy.save` / `renpy.load`
- 把解锁集合放进 `SaveRecord`（本版本鉴赏跨槽共享）
- 另写 JSON 文件绕开引擎存档（除非引擎槽无法保存自定义字段；若发生，仍只允许 `SaveStore` 内部改实现）

字段定义见 [接口设计-数据与存档](../设计/接口设计-数据与存档.md)。

## 7. 运行时

- 游戏只由 **Ren'Py 8 SDK / Launcher** 启动与打包。
- 禁止用系统 Python 或 venv 当运行时。
- 调试看引擎 traceback，不用 debugpy 挂脚本。
