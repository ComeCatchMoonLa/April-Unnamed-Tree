# 编码规范

- 目的：约束 Ren'Py / Python 实现风格，避免 AI 产出不可维护的大文件与额外功能。
- 读者：实现者、代码评审、AI 会话。
- 关系：目录与分层见 [架构设计](../设计/架构设计.md)；文件落点见 [接口实现约定](接口实现约定.md)。
- 版本：v1.3
- 日期：2026-09-20

## 1. 语言与运行时

- Ren'Py 8，脚本中的 Python 按 Python 3。
- 标识符英文 `snake_case`。类型/screen 名可用 `scr_` 前缀。
- 玩家可见文案中文。注释中文，说明「为什么」。
- 不引入第二语言、不引入 Web 框架。

## 2. 体量上限

| 项 | 上限 |
|---|---|
| 单文件 | 500 行 |
| 单函数 | 300 行（应远小于此；超过 80 行考虑拆） |
| 函数参数 | 5 个（含 `self` 则更应打 record） |
| 单目录文件 | 15 个 |

超限先拆文件，不准用「先写着」跳过。

## 3. 分层

- 节点表、CG 表、解锁条件、快捷键文案放 `game/data/`，禁止在章脚本里散落 `if node_id == ...` 做目录。
- 存档只通过 `SaveStore`。UI 只传 `slot_id` 与会话提供的 `LineRef`。
- 解锁只通过 `UnlockStore`。
- 章脚本只调用 `PlaySession` / 选择肢入口 / 对话 helper。
- screen 不写 `persistent` 字段。

## 4. 命名

| 种类 | 规则 | 例 |
|---|---|---|
| 节点 / CG / 章 ID | 与设计文档完全一致 | `ch1_start` |
| 函数 | 接口文中的名字 | `start_new_game` |
| screen | 接口文中的名字 | `scr_title` |
| label | 优先等于 `node_id` | `ch1_start` |
| `line_id` | `{node_id}:{四位}` | `ch1_start:0001` |

禁止为「更清晰」改 ID。要改必须先改设计文档并过设计评审。

## 5. Ren'Py 写法

- 避免巨型 `script.rpy`。入口文件只 `jump` / `call`。
- `init python` 按模块分文件，放 `game/system/`。
- 对话 helper 参数 ≤5。推荐 `(speaker, text, line_id)` 或一个 `LineDef` record。
- 插入新句：只追加新 `line_id`，不重排旧号。
- 不使用默认 save screen、rollback、skip、hide、confirm quit。Auto 必须用引擎默认 AFM。

## 6. 禁止项

与 [需求分析](../调研/需求分析.md)「明确不做」一致，代码评审视为缺陷：

- 实现回滚、Skip、Hide、退出确认
- 自管 Auto（pending/active、点击不退出）来替代引擎 AFM
- 鉴赏回放写槽
- 把解锁放进 `SaveRecord`（本版本）
- 程序绘制樱花、光尘、粉像素、转场闪白
- 播放 BGM/SE/语音
- 读用户系统字体
- 网页构建
- 为「方便」加设置项（音量、语言、改键、字体选择等）

## 7. 格式化

- `.rpy` 不跑 Ruff/Black。见 [开发环境](../调研/开发环境.md)。
- 缩进 4 空格。不混用 Tab。
- 保存时允许去行尾空白（trailing-spaces），但不得重排剧本空行语义。

## 8. 提交前自检

1. 文件/函数/目录未超限
2. 未新增未文档化的 screen、设置项、快捷键
3. `renpy lint` 已跑（改剧本后、出包前）
4. ID 与设计表一致
