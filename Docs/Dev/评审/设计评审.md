# 设计评审

- 目的：实现前强制检查设计是否可开工，避免 AI 在歧义文档上扩 scope。
- 读者：评审者、准备开写代码的会话。
- 关系：对照 [需求分析](../调研/需求分析.md) 与 `Docs/Dev/设计/`。不通过不准编码。
- 版本：v1.4
- 日期：2026-09-20

## 1. 流程

1. 阅读顺序按 [README](../README.md)。
2. 按下列清单逐条记 Pass / Fail。
3. Fail 必须指出文档路径与应改句子。
4. 输出：**通过** 或 **待改**。待改修文档后重评。
5. 玩法已拍板：评审改的是文档清晰度与一致性，不是重开需求（除非需求本身冲突）。

本轮文档落盘后应做一次设计评审再开工程。

## 2. 清单

### 2.1 需求覆盖

- 平台 Win + Android、不做 Web 已写进需求与验收
- 明确不做（回滚/Skip/Hide/确认/语音/程序美术）在需求与编码禁止项都有
- 单槽可扩展、解锁全局、白占位 CG 管线有对应设计

### 2.2 无冲突

- 「通关两次才出后日谈」已否决，与真选项立刻解锁后日谈不冲突
- 鉴赏回放不写槽 vs 节点自动存档：用 `play_mode` 区分
- 无字体设置 vs 表里差异：靠底色，不靠第二字体
- 标题显隐（主进度三态、里解锁后插在正下方）与「不灰显占位」已写进界面与操作
- 有槽不能从标题新开正篇，与无存档柜一致

### 2.3 接口映射验收

每一条 [验收清单](../测试/验收清单.md) 都能指到接口函数或 screen：

- TC02/03 → `scr_title` 显隐（无槽新的游戏 / 有槽继续；解锁后主键为后日谈）
- TC04/05/06 → `SaveStore` + `commit_leave` + `on_node_reached`
- TC07 → `enter_replay` 不写槽
- TC18/19 → `toggle_afm` + 引擎 AFM
- TC11/12 → `run_choice_true`
- TC15 → `sync_inner_dim`

若某 TC 只能靠「适当处理」，本项 Fail。

### 2.4 可实现性

- 无「适当」「尽量」「看情况」作为唯一说明
- 色值、CPS 三档（25/50/80）、afm 三档、安卓隐藏窗口行已给默认
- 函数参数 ≤5；复杂状态在 `PlayContext` / `LineRef`
- 目录预算：data/system/ui/script 均可控在 15 文件内
- 节点 29、CG 4、槽 `"0"`、ID 禁止改名已声明

### 2.5 环境

- Py Dev 插件增删与 `renpy lint` 已在 [开发环境](../调研/开发环境.md) 写清
- 本阶段不强制 `.cursor/rules`（见代码评审文）
